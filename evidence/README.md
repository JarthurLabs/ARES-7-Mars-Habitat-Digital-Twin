# Evidence register

This directory contains proof generated by running ARES-7. It separates local
software evidence, Azure infrastructure evidence, and live-path evidence so a
screenshot is never asked to prove more than it shows.

## Provenance rules

- `Verified` means the artifact exists and was produced from the checked-in
  implementation or an explicitly identified real Azure resource.
- `Pending` means no public artifact exists and the README must not claim the
  corresponding service or behavior is live.
- Portal screenshots must be cropped or redacted, never recreated or mocked.
- Raw logs and machine-readable output are preferred alongside screenshots.
- Secrets, tokens, connection strings, SAS values, tenant IDs, subscription
  IDs, and personal email addresses do not belong in this directory.

## Local screenshot provenance

The local screenshots were captured from the real application
after fonts were bundled and after the scene metadata fix. They show
`SCENE MODULES · 6 MODULES`, `dtmi:ares7:Habitat;1`, and the deterministic
local simulator provenance. The approval and containment images were produced
by advancing the actual UI through the drill rather than editing the display.
The 5 August desktop and mobile captures came from the built static artifact;
the desktop frame deliberately leaves the Power Control twin inspector open.

The Azure captures show real Azure CLI output in Cloud Shell. Subscription,
tenant, and personal identifiers are not present. The deployment record is a
concise redacted transcript; it is not raw credential-bearing output.

inspection and the complete approval-to-containment path.
